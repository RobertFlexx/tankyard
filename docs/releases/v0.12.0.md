# Tank Yard v0.12.0

A new scripting engine for mods, HUDs that mods can draw, and a faster, cooler Metal renderer on every Mac. Everything in [v0.11.8](v0.11.8.md) is included.

## Mods

- Script packs now run on Luau instead of LuaJIT. Existing packs work unchanged and play out the same: numbers, text formatting, sorting, bit operations and errors all behave as they did, and the same match with the same packs ends the same way on either engine.
- Scripts take about a fifth less time per tick, allocate about three quarters less, and load in about half the time (60 bots, four packs). Packs are compiled once per server instead of every round.
- Pack authors get Luau's additions: `continue`, `+=` and friends, `if` expressions, string interpolation, `//`, type annotations, and libraries such as `buffer`, `utf8`, `bit32`, `table.find` and `string.split`. `goto continue` is converted to `continue`; see [Luau for script authors](../modding.md#luau-for-script-authors).
- Packs can draw their own HUD: text and progress bars on everyone's screen or one player's, with `tankyard.hud(...)` in scripts or the `hud` action in data packs. The server decides what each player sees and sends it only when it changes, so HUDs never fall out of step with the game. See [HUD widgets](../modding.md#hud-widgets).
- Approving a flagged pack is now bound to a SHA-256 digest of its files, so a changed pack can't pass as the one you approved. Existing approvals carry over for packs that haven't changed.
- Library calls given huge or invalid numbers (such as `string.rep("x", 2^31)`) now behave the same on Intel and Apple silicon.

## Macs

- The Metal renderer no longer makes the CPU wait for the GPU at the end of every frame. The next frame is prepared while the last one draws, which cuts frame time and lets both chips idle sooner.
- On Apple silicon and Intel integrated graphics, Metal now uses memory shared with the CPU instead of copying it.
- On Intel Macs with AMD graphics, shapes could be drawn with stale colors or positions from earlier in the frame. Fixed.
- Some Metal draw calls passed numbers with garbage in their upper bits on Apple silicon; Apple's validation layer now runs clean.
- New **Battery saver** setting (Settings → Display): games run at up to 60 fps and menus at 30, and Macs with two GPUs use the integrated one after a restart. Checking for Metal at startup no longer wakes the discrete GPU.
- Menus hold 60 fps on 120 Hz displays even with vsync on, and windows hidden behind others draw at 30 fps.
- Intel builds were checked under Rosetta: the same matches play out bit for bit on Intel and Apple silicon.

## Network

- Your input is sent as soon as each frame's update finishes, before drawing, shaving a few milliseconds off every action.
- Servers can send up to 60 snapshots per second (`snapshot_rate`, previously up to 30) for smoother play where bandwidth allows.

Protocol **23**. Servers still welcome v0.10 and v0.11 clients, which play normally without mod HUDs. v0.12 clients need a v0.12 server, so update servers first.
