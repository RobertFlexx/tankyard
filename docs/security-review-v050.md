# v0.5.0 scoped review

This update adds player-hosted party entry, an uptime map scheduler and creator event commands. It does not change the pinned creator/central-owner keys or grant creator powers to ordinary server roles.

Party invites contain a random 32-byte Ed25519 seed and a bounded literal IP endpoint. Servers keep only the public verification key. A fresh nonce binds the entry proof to the server ID, connection ID and ephemeral administration public key. Invalid, missing, replayed or substituted proofs cannot create a player. Handshake timeouts and existing bounded message/rate limits apply. Possession grants membership only; the leader's Owner grant still travels through the process-local channel and binds the same live administration key. The eight-player limit bounds party resources. Invites stay out of saved server history. Direct unsecure UDP retains the documented transport limitations; the invitation is not server authentication, encryption or NAT traversal.

Axiom transformations and attacks use the existing signed, sequenced, audited creator command path and consenting host policy. Gameplay input has no transformation command. The trusted core entry point checks living creator identity, legal placement and per-attack cooldowns. Shots use normal collision/protection rules, finite bounded stats and the configured projectile cap. Reset and policy revocation remove the form and its projectiles; class changes/upgrades cannot replace the form's authoritative health/radius. Ordinary owners, central owners and invited party members receive no creator powers.

Rotation uses server process elapsed time outside the idle simulation pause. It executes at most one transition per update, preserves its two-hour schedule across rounds, and selects from the validated map catalog. Clients receive a bounded countdown; it has no effect on server authority. Sparse map emblems and tree geometry are rendering only. The ambient match has fixed small budgets, never loads mods or connects to a network, and cannot earn personal progress.

Verification includes the complete public Rust suite, localhost party admission/replacement/restart tests, proof context substitution tests, empty-server uptime rotation tests, form authorization/cooldown/revocation tests, layout coverage tests, strict Clippy and existing installer fixtures. Native GUI captures cover 800×600 at 140% UI and 1280×800, including real hosted parties and local creator credentials. Cross-platform packages and installed-package tests run in the tagged workflow. Private identity seeds and credential binaries remain excluded from public packages. Existing dependency and transport limitations from the earlier security review remain; this is not a claim that all exploitable defects are eliminated.
