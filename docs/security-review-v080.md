# Party and base review: v0.8.0

Party configuration reuses the authenticated, signed, sequenced and round-bound administration channel. A new bounded command applies the mode, map, bot difficulty, party slots, starting level and arena dimensions atomically. It requires the server's Configure permission and an active party configuration; a custom client that changes its local permission list still receives a server rejection. The invitation and creator identity cannot grant the process-local owner role.

The optional party relay gives each leader an independent ephemeral host key. Its public key identifies the room. A random server challenge is signed over a protocol domain, role, room, nonce and (for registration) invite public key. Guests separately prove invite entry before receiving a forwarding slot. Entry credentials cannot replace a host, and captured signatures cannot be replayed for another challenge or role. Invite seeds and creator/central-owner credentials never travel in relay URLs or registration payloads. TLS certificate verification is inherited from the existing WebSocket client.

The relay permits at most 32 rooms and eight guest transports per room, within the existing global connection limit. Each queue, WebSocket frame, write buffer and batch is bounded. Independent direction budgets constrain guest packets; multiplexed host budgets account for eight participants, including simultaneous voice streams. Handshakes have deadlines, idle sockets expire, and disconnect guards remove memberships. In v0.8.1, full datagram queues drop excess packets and preserve membership; genuinely closed receivers are removed. Neither path accumulates an unbounded queue. This is a shared service with finite capacity; capacity limits do not establish an assurance against all denial-of-service attacks.

The leader's tunnel creates connected UDP sockets only to its supplied loopback match endpoint. Remote frames contain a connection number and bounded datagram, never an arbitrary destination. Existing netcode, invite proofs, server authority, Bastion validation, role checks and audit policy remain in force after transport forwarding. Relayed guests receive no owner capability. Manual/LAN setup disables all automatic external networking.

Base protection is computed from authoritative team, hull and animated arena bounds at damage time. Clients cannot claim protection with an input bit. All tank damage routes use the common damage function; Smasher counters also reject protected hulls before applying recoil. Team spawns and map cover use the same geometry. Cooperative and Infection modes deliberately do not gain permanent invulnerability zones.

Validation covers forwarded/lossy UDP admission, an unreachable direct address with two live relayed clients, chat and round persistence, entry impersonation, host impersonation using an invite key, signature binding, disconnect cleanup, hostile-client configuration, live projectile damage and all built-in maps at multiple sizes and border scales. Native desktop checks cover the retained party, mode transitions and responsive layouts. This is a scoped review, not a claim that every game or network defect has been eliminated. Private password gates and signing credentials remain separate from public artifacts.
