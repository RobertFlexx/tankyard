# Party update review: v0.7.0

Party rosters are issued only by an invite-authenticated server. Membership is bounded to eight unique connections and entities with validated names and tank classes. The leader flag derives from the existing local Owner grant; a name, invite seed or menu-presence message does not confer ownership. Presence is informational and grants no protection or gameplay privilege. The existing challenge/signature, moderation, replay, rate and transport policies still apply. Protocol 19 prevents old peers from misreading the added control messages.

The client retains the same connection while browsing menus and sends neutral gameplay input. Chat uses the existing server-authoritative room membership, name assignment, bounded history and rate limits. Local voice mutes filter incoming playback, buffered samples and decoders, keyed through stable connection IDs rather than recyclable tank IDs. Leaving a party explicitly closes its transport; an accidental new-session action cannot replace it.

Public address lookups use fixed HTTPS endpoints, certificate verification, disabled proxy inheritance/redirects, timeouts and response-size limits. They receive no invite or identity credential. Router discovery accepts only numeric HTTP endpoints on the responding private/link-local IPv4 device, with bounded packets, attempts and deadlines. Device/SOAP responses have byte, XML nesting and event limits; DTD/entity declarations are rejected. No arbitrary hostname or external/loopback SSDP URL is fetched. Manual/LAN setup disables both lookups and router discovery.

Forwarding is UDP-only on a random high external port. The game checks that the entry is absent, requests a finite ten-minute lease, verifies the mapped client/port/description and lease, and renews only its own entry. It never falls back to a permanent lease. Cleanup verifies ownership before deletion; a crash leaves a finite lease to expire. Double NAT/CGNAT, host firewall restrictions and remote reachability are reported as limitations instead of being treated as solved by a public-IP lookup. The invite endpoint remains editable for an operator's manual forwarding.

Checks cover real local party admission, menu presence, chat, round transitions, bot replacement, distant members and disconnects, plus roster bounds, URL restrictions, XML/entity/depth limits and responsive party geometry. Native host/guest review covers clipboard copying, text/chat input, local mute controls, retained menu connections, resume and explicit leave. This review is scoped to the changed paths; it does not claim the game has no remaining bugs or vulnerabilities. Private password gates and credentials are unchanged and remain outside public artifacts.
